# 通用界面审美规范

这是一套**跨项目通用**的审美和可用性规范，不绑定任何品牌的颜色或字体。它解决两件事：

1. **AI 常犯的小错误**：字太小、行距太紧、元素错位、加载时布局跳动、内容被裁切、状态缺失、文案中英混杂。
2. **AI 味**：模型倾向于选“最常见、最安全”的方案（蓝紫渐变、Inter 字体、居中大标题 + 三张功能卡、毛玻璃、到处都是圆角卡片和柔和阴影），结果所有界面长得一样，一眼就能看出是 AI 做的。

项目自己的品牌色、字体、组件库是另一层，写在项目的设计变量里。本规范只规定**怎么选、怎么用、什么不能做**。

## 参考文件

| `references/layout-interaction.md` | 做页面、弹窗、列表、表单时读。稳定布局、局部滚动、弹窗骨架、状态反馈 |

## 一、核心原则

1. **克制**：每屏只有一个视觉重点、一个主按钮。装饰必须有理由，说不出理由就删。
2. **稳定**：切换 tab、步骤、分页、加载完成时，外框、按钮、页脚位置不动。
3. **聚合**：同一件事在一处完成（同一个弹窗或面板），不让用户在页面之间来回跳。
4. **可读优先于“看起来整齐”**：宁可让数据区局部滚动，也不把字号压到 12px 以下、不裁切内容。
5. **具体而不是通用**：配色、字体、布局都从产品本身出发。如果一个设计放在任何同类产品上都成立，说明它还没有设计过。
6. **一致**：颜色、字号、间距、圆角只从一套刻度里取值，不即兴发明。

## 二、动手前先做的决定（写下来再写代码）

1. **这是什么界面、给谁用、主要任务是什么**：工具类后台要密度和效率，落地页要一个清晰的主张，阅读类要舒适的行宽和行距。
2. **找一个具体参照**：说出一个真实产品或风格作为参照（例如“Linear 的列表密度”“Stripe 文档的排版”），不要用“现代、简洁、高级”这类空词。
3. **定设计变量**：4–6 个具名颜色（含语义色）、1–2 个字体及各自用途、字号刻度、间距刻度、圆角档位。项目已有就沿用，不新增。
4. **选一个记忆点**：整个界面只允许一个特别的地方（一种字体、一个插图、一个动效），其余保持安静。
5. **列出这个界面要避开的 AI 味**：对照 `anti-ai-look.md`，把容易犯的几条明确写进计划。

## 三、硬规则

### 排版
- 正文最小 14px（中文界面后台可用 13px），辅助文字最小 12px。**任何文字都不小于 12px。**
- 中文正文行高 1.5–1.75；标题 1.2–1.35。正文行宽 35–45 个汉字或 65–75 个英文字符。
- 层级靠字号、字重、颜色、间距拉开，至少有 3 级可分辨；不要只有一种字号。
- 不用渐变文字；不把标题里的某一个词单独染色或改成斜体来“强调”；中文不用斜体。
- 中文不加字距；英文全大写只用于极短标签。
- 多行标题用 `text-wrap: balance`，段落用 `text-wrap: pretty`，避免末行只剩一两个字。
- 数字列用等宽数字（`font-variant-numeric: tabular-nums`）并右对齐。

### 颜色
- 只用设计变量，不在业务代码里写十六进制。
- 中性色占绝大部分，强调色只用于“行动”和“当前状态”，面积小于 10%。
- 语义色固定：成功绿、警告黄、错误红；强调色不兼任警告。
- 文字对比度 ≥ 4.5:1（大字 ≥ 3:1），控件边界和图标 ≥ 3:1。深浅两种背景上要分别检查。
- 彩色背景上不用灰色文字，改用该颜色的深色调或白色。
- 不用默认的蓝紫渐变、青色霓虹、发光边框、光晕背景。

### 布局
- 用间距表达分组：组内紧、组间松；标题离自己的内容近、离上一块远。
- 不嵌套卡片（卡片里再放卡片）；用间距、分隔线、标题层级代替。
- 同一层级的元素不必都是一样大小的卡片；按重要程度安排大小和位置。
- 不做“居中大标题 + 两个按钮 + 三张功能卡”的默认落地页结构，除非内容确实如此。
- 框架不滚动，长列表放进固定尺寸的区域内局部滚动，滚动条可见。永远不裁切内容。

### 组件与交互
- 每个页面/弹窗只有一个主按钮；危险操作用红色且与主按钮分开放。
- 按钮文字用具体动词（“保存修改”“导入账号”），不用“提交”“确定”这种笼统词，也不在按钮后面习惯性加 “→”。
- 图标用一套线性图标库，统一粗细和尺寸；不用 emoji 当图标。
- 每个数据区都要有加载、空、错误三种状态，尺寸和正常状态一致。
- 可点击区域 ≥ 24×24px；键盘可操作，焦点清晰可见。

### 动效
- 动效只用来说明“发生了什么变化”（展开、出现、移动），时长 100–300ms，缓动平滑不回弹。
- 不做每个区块的淡入上滑、悬停放大卡片、脉冲状态点、跑马灯、装饰性闪烁光标。
- 支持 `prefers-reduced-motion`。

### 文案
- 说清楚“能做什么、结果是什么”，不写“赋能、一站式、全新体验、Supercharge、Unlock、Seamless”这类空话。
- 不用“不是 X，而是 Y”这种口号句式；不滥用破折号。
- 同一操作在整个流程里用同一个名字。
- 报错说明发生了什么、怎么解决；空状态说明为什么空、下一步做什么。
- 界面语言统一：中文界面不残留英文键名，不出现 `undefined`、`NaN`、`null`。

## 四、工作流

1. 读 `anti-ai-look.md`，再按第二节写下设计决定。
2. 先搭骨架（框架、分区、固定区域），再填内容，最后加细节。
3. 实现时只用设计变量和现有组件。
4. **截图自审**：在桌面（1440×900 和 1280×720）和手机（375×812）各截一张，按第五节清单逐条过；再用 `anti-ai-look.md` 数一数命中了几条 AI 味特征，命中 3 条以上视为不合格。
5. 删减：去掉一个装饰后界面没有变差，就删掉它。重复直到删不动。

## 五、自检清单

**小错误**
- [ ] 没有小于 12px 的字；行高合适；正文行宽不过长。
- [ ] 同一行的输入框、按钮顶部对齐；标签和说明位置统一。
- [ ] 切换 tab / 分页 / 加载完成时，外框和按钮不跳动。
- [ ] 窄屏和矮屏下没有内容被裁切、没有横向滚动、弹层没有被容器截断。
- [ ] 加载、空、错误状态都有，尺寸一致。
- [ ] 没有 `undefined` / `NaN` / 裸英文键；数字有格式化；空值显示 `—`。
- [ ] 对比度达标（深浅两种背景都查过）；焦点可见；点击区足够大。
- [ ] 标题层级不跳级（h1 → h2 → h3）。
- [ ] 列表的滚动条只出现在数据行区域，表头、筛选工具栏、分页都在滚动容器外面；不用 sticky 把表头留在滚动容器里。
- [ ] 所有提示信息（成功、失败、接口错误原因、警告）统一用 toast，不写进容器内；容器里没有按条件出现的提示行、红字错误行、警示条。有提示和没提示时布局完全一致。
- [ ] 报错只显示当前界面语言，不把“English（中文）”整段露给用户。
- [ ] 图表在没有数据时坐标轴不出现重复刻度（如 1、1、0）；缺名称的行显示 `—`。
- [ ] 同一张卡片里的状态文案不自相矛盾（例如“未达等级”配“已达到最高等级”）。
- [ ] 全局顶栏里的按钮不用主按钮样式，否则每页都会有两个主按钮。

**AI 味**
- [ ] 没有蓝紫渐变、渐变文字、光晕背景、霓虹发光、满屏毛玻璃。
- [ ] 没有千篇一律的同尺寸圆角卡片网格；没有卡片套卡片；没有卡片左侧彩色竖条。
- [ ] 没有图标方块叠在标题上方的“功能卡”套路；没有标题上方多余的小标签或徽章。
- [ ] 没有 emoji 图标、装饰性网格背景、粗糙的 SVG 插画。
- [ ] 没有每个区块都淡入上滑、悬停放大、脉冲小圆点、跑马灯。
- [ ] 文案没有营销空话、口号句式、到处的破折号和箭头。
- [ ] 能说出这个界面和“任何同类产品”的区别在哪里。
