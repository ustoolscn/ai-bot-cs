# AI 味特征清单

**为什么会有 AI 味**：模型总是倾向于网上最常见、最“安全”的选择。单看每一个选择都不算错，但叠在一起就成了“谁都能做出来”的模板脸。去 AI 味的办法不是追求花哨，而是**每个选择都有理由，并且贴合这个产品**。

**判定**：同一个界面命中 3 条及以上，就算有明显的 AI 味，需要返工。

**用法**：做设计前先把可能踩的几条写进计划；做完后截图逐条对照。

## 颜色

| 特征 | 为什么是 AI 味 | 替代做法 |
| --- | --- | --- |
| 蓝紫 / 靛紫渐变（按钮、背景、标题） | 最常见的默认配色 | 从产品本身取主色；按钮用纯色 |
| 深色背景 + 青色/霓虹色 + 发光边框 | “科技感”的套路 | 深色模式只降低亮度，强调色保持克制，不加辉光 |
| 背景大光晕、径向渐变、柔和聚光灯 | 用光效假装有重点 | 用间距、对比、标题层级制造重点 |
| 渐变文字（`bg-clip-text`） | 纯装饰 | 单色，靠字号和字重强调 |
| 米白/米色底 + 陶土橙 + 衬线标题 | 已经从“有品位”变成新的默认模板 | 只有产品气质确实需要时才用，并且要有别的辨识点 |
| 近黑底 + 酸绿 / 朱红单一强调 | 另一种常见模板 | 同上 |
| 彩色背景上的灰色文字 | 发灰、对比不够 | 用该底色的深色调或白色 |
| 强调色到处都是 | 没有重点 | 强调色面积小于 10%，只给“行动”和“当前状态” |

## 字体与排版

| 特征 | 替代做法 |
| --- | --- |
| Inter / Roboto / Poppins / Geist 当唯一字体，没有考虑过别的 | 按产品气质选字体；如果确实用这些，靠字号、字重、间距建立个性 |
| 层级扁平：标题和正文差不多大 | 至少 3 级可分辨，标题与正文字号比 ≥ 1.25 |
| 标题上方加一行小号大写标签（eyebrow），内容和标题重复 | 删掉，或把信息并进标题 |
| 标题上方放一个胶囊徽章（“✨ 全新发布”） | 删掉，或改成标题里的一句话 |
| 标题里单独一个词染色 / 斜体 / 渐变 | 整句同色；需要强调就改写句子 |
| 斜体衬线大标题当“高级感” | 只有内容需要时才用；中文不用斜体 |
| 首屏超大标题占满一屏 | 缩短标题或缩小字号，首屏要能看到下一步 |
| 字距压得很紧（`tracking-tighter`），或正文加宽字距 | 标题最多轻微收紧，正文保持默认 |
| 小号等宽字体当“数据标签”装饰 | 等宽字体只用于代码、ID、密钥、需要对齐的数字 |
| 段落末行只剩一两个字，标题末行很短 | `text-wrap: pretty` / `balance` |
| 两端对齐 | 左对齐 |
| 正文过小（< 14px）、行距过紧（< 1.4） | 正文 14–16px，中文行高 1.5–1.75 |

## 布局与结构

| 特征 | 替代做法 |
| --- | --- |
| 居中大标题 + 双按钮 + 三张功能卡（落地页模板） | 从内容出发：最能代表产品的东西放在首屏 |
| 一排排同尺寸、同圆角、同阴影的卡片 | 按重要程度分组、改变大小；列表数据用表格 |
| 卡片套卡片 | 拉平：用间距、分隔线、标题层级 |
| 圆角方块图标叠在标题上方（功能卡套路） | 图标放在标题左侧，或去掉底块 |
| “大数字 + 小标签”统计条当默认首屏 | 只有数字本身能说明产品价值时才用 |
| 每个区块用一样的间距 | 组内紧、组间松；标题离自己的内容近 |
| 连续几个区块结构一模一样 | 改变宽度、分栏、对齐方式 |
| 没有顺序的内容也加编号（01 / 02 / 03） | 编号只用于真正的步骤或时间线 |
| 横向滚动列表两端贴边 | 两端留出与内边距相同的空白 |
| 下拉菜单、弹出层被容器裁掉 | 渲染到容器外（portal），或允许溢出 |
| 内容溢出容器、出现横向滚动 | 允许换行，或放进局部滚动区 |

## 装饰与质感

| 特征 | 替代做法 |
| --- | --- |
| 满屏毛玻璃（`backdrop-blur`）导航栏和卡片 | 只在真正有内容叠在下面时使用 |
| 细边框 + 大面积柔和阴影同时用 | 二选一 |
| 圆角卡片左侧加粗彩色竖条 | 只有表示状态（如告警）时用；否则删掉 |
| 所有东西一律 `rounded-2xl` 或更大 | 圆角按元素尺寸分档：小控件 6–8，按钮输入 8–10，卡片 12–16 |
| 装饰性网格线背景、斜条纹、噪点、光斑 | 纯色底；网格只给画布、地图等需要度量的场景 |
| 渐变胶囊按钮 | 纯色按钮，圆角与其他控件一致 |
| 手画感粗糙的 SVG 插画、圆圈方块拼的占位插图 | 用精心制作的插图、真实截图或照片，或者不放 |

## 动效

| 特征 | 替代做法 |
| --- | --- |
| 每个区块滚动进入时淡入 + 上滑 | 最多一个有编排的入场；内容默认可见 |
| 悬停时卡片放大、上浮、加阴影 | 悬停只轻微改变底色或边框 |
| 状态点无条件一直脉冲 | 只有真实进行中的任务才动；进行中的状态应该动起来 |
| 跑马灯、自动轮播 | 静止，或提供暂停 |
| 有实时状态却做成静态数字和静态列表 | 进行中、进度、数值变化用动画表达（见 SKILL.md 动效） |
| 不能输入的地方有闪烁光标 | 删掉；只在正在流式输出时显示 |
| 回弹、弹性缓动 | 平滑减速，100–300ms |
| 没处理 `prefers-reduced-motion` | 减少动效时去掉位移和缩放 |

## 图标与图片

| 特征 | 替代做法 |
| --- | --- |
| emoji 当图标（🚀 ⚡ ✨ 🎯） | 同一套线性图标库，统一线宽和尺寸 |
| 混用多套图标库 | 只用一套 |
| AI 生成的抽象图、通用素材图 | 真实的产品截图、数据或照片 |
| 图片上盖一层几乎不透明的遮罩 | 减轻遮罩，或不用图片 |
| 图片坏链、空占位 | 用真实资源，或删除位置 |

## 文案

| 特征 | 替代做法 |
| --- | --- |
| “赋能、一站式、全新体验、开启…之旅、释放潜能、Supercharge、Unlock、Seamless” | 写清楚用户能做什么、得到什么 |
| “不是 X，而是 Y”“告别…，拥抱…”口号句式 | 直接说区别 |
| 到处是破折号、冒号、三连排比 | 用句号把话说完 |
| “受到 10000+ 团队信赖”之类没有出处的社会证明 | 没有真实数据就不写 |
| 按钮和链接后面习惯性加 “→” | 只在确实表示“前往下一步”时用 |
| 同一张卡片里同一句话出现两次 | 只保留一处 |
| “提交”“确定”“点击这里” | 具体动词：“保存修改”“导入 20 个账号” |
| 中英文混写、技术键名直接露出 | 统一语言；技术细节折叠进“详情” |

## 中文界面特有的 AI 味

- 中文用斜体、中文加大字距、中文全角标点前后多余空格。
- 中英文、数字之间不加空隙或乱加空格：统一一种规则（推荐中英文之间留半角空格，或依赖字体自带间距，二选一保持全站一致）。
- 机翻腔：“您的账户已经被成功地创建了”。改成“账号已创建”。
- 一句话里塞满“智能、高效、极致、全方位”。
