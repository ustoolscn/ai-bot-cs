# 布局与交互

这些规则来自实际使用中反复出现的不适感，适用于后台、控制台、工具类界面；落地页和阅读类页面只适用其中“稳定”“状态”“不裁切”几条。

## 1. 框架不滚，数据区滚

- 页面、弹窗、抽屉、卡片的外框固定，不整体滚动。
- 账号、模型、日志、请求明细、批量结果这类长列表，放进**尺寸固定的数据区**内局部滚动：
  - 表头、筛选栏、分页栏固定；
  - 滚动条**可见**，并用 `scrollbar-gutter: stable` 预留位置，出现滚动条时内容不左右跳；
  - 不靠隐藏滚动条来掩盖长列表。
- 表单和配置内容优先用分栏、折叠、分区来放下，而不是滚动。
- 屏幕太矮放不下时，只让内容区滚动，页头和页脚不动。**绝不用 `overflow: hidden` 裁掉字段**，那样用户根本点不到。
- 手机上允许整页纵向滚动，弹窗内仍优先固定布局。

反面教训：为了“不滚动”把字号压到 9–10px、把每页条数按窗口高度动态计算，结果字看不清，窗口一变页码就跳。**可读性优先于不滚动。**

## 2. 切换不抖动

- 带 tab、分段控件、步骤条的容器使用固定高度，高度取所有 tab 中**最高的那个**，不是全站统一一个高度（否则矮内容下方一大片空白）。
- 切换只替换内容区，外框尺寸、按钮、页脚位置都不变。
- 一种实现方式：所有 tab 叠在同一个网格单元里同时渲染，只切换可见性，容器自然取最高值，表单状态也不丢。
- 内容量差异很大的分区：左侧分区导航 + 固定内容区 + 统一的分组骨架。
- 加载、空、错误状态与正常状态尺寸一致（骨架占位、空状态撑满同一区域）。
- 所有提示信息统一用 toast（站点的弹出提示），不写进容器内。按条件出现的提示行、错误行、警示条一律不做，即使预留了固定高度也不做，因为空着的预留位本身就是多余的空白。容器内只放始终存在的固定状态文字。
  Z-API 实例：上游额度面板曾把错误、统计、冷却提示做成容器底部的条件行，出现时整体偏移（2026-11-02）。
- 批量操作栏未激活时隐藏但保留位置（`visibility: hidden`，不是 `display: none`）。
- 分页每页条数固定（管理列表默认 100 条），不随窗口高度变化。

## 3. 一件事在一处完成

- 同一件事的操作（导入、编辑、绑定、配置）放在同一个弹窗或面板里完成。
- 需要二级操作时叠一层弹窗，关闭后回到原处；不跳到另一个页面让用户再找回来。
- 不留“去某某页面设置”的小链接当功能入口。
- 同一个对象只有一个编辑入口、一个名字；多个入口打开同一个编辑器时，名字必须一致。

## 4. 弹窗骨架

```
┌────────────────────────────────────────────┐
│ [图标] 标题                            [×] │ 页头：固定高度，一行说明
│        一行说明                            │
├──────────┬─────────────────────────────────┤
│ 分区 1   │ 分组标题           [分组操作]   │
│ 一行说明 │ ┌──────────┐ ┌──────────┐       │ 内容：分组 + 两列表单
│ 分区 2   │ │ 字段     │ │ 字段     │       │ 放不下时只有这里滚动
│ 分区 3   │ └──────────┘ └──────────┘       │
│          │ ───────────────────────────     │
│ 范围说明 │ 下一个分组…                     │
├──────────┴─────────────────────────────────┤
│ [删除] 状态说明              [取消] [保存] │ 页脚：危险操作在左，主操作在右
└────────────────────────────────────────────┘
```

- **高度不超过屏幕**：弹窗始终垂直居中，最大高度为视口高度减去上下各 24–40px。页头和页脚固定，只有内容区内部滚动；遮罩层本身不滚动。抽屉同理。
- 宽度分三档：窄（确认、单字段，约 448px）、中（约 768px）、宽（约 1024px）。同一功能的弹窗尺寸稳定。
- 有分区的弹窗用左侧分区栏（约 200px），每项包含图标、名称、一行说明；手机上变为顶部横向条。
- 内容按主题分组：分组标题 + 一行说明 + 右侧操作，组与组之间用细线分隔。
- 破坏性确认：页头图标用红色，确认按钮实心红色。
- 打开时焦点进入弹窗，Esc 只关闭最上层，关闭后焦点回到触发按钮。

## 5. 表单

- 字段两列排布（手机一列），标签在上，间距紧凑。
- 同一行的输入框顶部必须对齐：说明文字长短不一时，放到悬停提示或统一放在字段下方。
- 开关统一用“标签 + 说明在左、开关在右”的行样式，不要一会儿有边框一会儿没有。
- 长文本（JSON、批量导入）用固定行数的多行框，内部滚动。
- 实时校验容易出错的输入；错误提示放在字段下方并标红字段边框。
- 提交中按钮显示加载状态，宽度不变。

## 6. 列表与表格

- 行数据用表格，不用卡片网格。
- 行高 44–56px，一屏能看到 10 行以上；每格最多两行（主信息 + 小一号的次要信息）。
- 次要统计放到悬停提示或行详情里，不要每格塞三四行小字。
- 固定列宽；复选框列、操作列不能被挤压截断。
- 首列放最能识别这一行的信息（名称 + ID），操作列在最右。
- 数字右对齐、等宽数字；空值显示 `—`。
- 用户反映太挤时，提供“紧凑 / 标准”密度切换并记住选择，而不是改默认值。

## 7. 按钮层级

- 每个页面、每个弹窗只有一个主按钮（实心强调色）。
- 其他操作用描边或文字按钮；同一页面不出现三种以上强调样式。
- 危险操作：可撤销的入口用浅红，不可撤销的确认用实心红。
- 页头按钮尺寸统一；表格行内用小号按钮或图标按钮。
- 纯图标按钮必须有文字提示（`aria-label` + 悬停提示）。

## 8. 导航与信息架构

- 导航顺序跟着用户的主线流程排列。
- 导航名称与页面标题一致。
- 同一个位置的按钮含义不能随页面变化（例如顶部按钮一会儿是“新建”一会儿是“返回”）。
- 进入沉浸页面（如对话）时保留窄版导航，让用户知道自己在哪、怎么回去。
- 公告等长文本单行截断，点击查看全文；不做跑马灯。

## 9. 文案与国际化

- 所有可见文案都经过翻译函数；切换语言后不残留另一种语言。
- 首次访问的默认语言按产品主要用户确定，而不是只看浏览器语言。
- 数值统一走格式化函数；缺失值显示 `—`，不显示 `undefined`。

## 列表的滚动区域不含表头

- 滚动容器只装数据行。表头、筛选工具栏、分页放在容器外，用独立的一行或一张表，列宽规则与数据行一致，并同样设置 `scrollbar-gutter: stable` 保持对齐。
- 不用 `position: sticky` 把表头留在滚动容器里：滚动条会从表头位置开始，看起来像整张表在滚。
- Z-API 的 `DataTable` 已按此实现；自己写的列表（网格行、手写 table）同样遵守。
